# Game architecture
Existing Next.js/TypeScript/React app; Three.js or React Three Fiber (choose one rendering integration); Rapier physics; DOM HUD; Web Audio. One shared fixed-step physics core, event bus, scoring ledger, input abstraction, camera, asset loader and audio. Mode-specific rules/config/arena layout. Do not bake HUD into GLB.
Suggested isolated module (adapt to repo): `football-pinball/core/{physics,clock,input,events,score}`, `modes/{pvp,crash,penalty,rush}`, `ui/`, `assets/`, `tests/`. Physics step suggested 1/120s with accumulator, capped render delta, interpolation; collider categories ball/rail/boot/player/keeper/goal/target/drain. Named events with dedupe IDs and tick ordering.
Online: separate persistent authoritative realtime match service; frontend on Vercel, Supabase for user/results persistence only. Send player inputs, authoritative snapshots, reconcile score; never trust client claims. Crash verified leaderboards likewise require authoritative canonical simulation and signed result, not only browser replay.
Performance: GLB lazy loading by mode, compressed textures, LOD, low-cost collider proxies, adaptive resolution, real iPhone/Android profiling. No deployment per micro-change.
