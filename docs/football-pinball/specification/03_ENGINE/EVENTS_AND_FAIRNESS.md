# Event schema and fairness
Event envelope: eventId, sessionId, authoritativeSequence, tick, type, actorId, ballId, targetId, ruleVersion, payload. Types: MATCH_CREATED, TOSS_DECIDED, KICKOFF, FLIP_DOWN, FLIP_UP, BALL_LAUNCHED, COLLISION, TARGET_HIT, PERFECT_KICK, GOAL_SCORED, KEEPER_SAVE, BALL_DRAINED, COMBO_CHANGED, BANK_REQUESTED, BANK_ACCEPTED, BANK_REJECTED, TIME_EXTENDED, MULTIBALL_STARTED, ROUND_ENDED. Only trusted engine generates score/goal/collision events.
States: READY -> COUNTDOWN/TOSS -> ACTIVE -> PAUSED/RESET -> ENDED. Crash terminal BANKED/DRAINED. Penalty ATTEMPT_RESOLVED/RELAUNCH. All state transitions explicit and tested.
For Crash, 'provably fair' is a claim requiring verified canonical deterministic replay, publicly documented score algorithm, input/event integrity and independently verifiable signatures. Commit-reveal of RNG does not prove physics-based loss is fair. Sign and hash ranked outcomes and provide verification tool before making claim. Same-tick collision/drain precedes bank input. Physics settings cannot depend on multiplier.
